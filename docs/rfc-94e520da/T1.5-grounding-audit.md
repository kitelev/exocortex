## Documented Homoiconicity Exceptions

Per RFC `c78cc5c8-076c-4509-9e22-6f0257c51df4` (Homoiconicity Invariant v0.2) Q3 corollary applied through RFC `18407cb2-9554-4897-9213-17321f9dd434` (T1.5 closure, 2026-05-17 Path B):

| Service id                   | Exception clause                                                                      | Rationale                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `rollbackStatus`             | **Q3.a** — ядро обработки over **non-RDF substrate**                                  | Temporal-stack pop over the `_history` array. Not a triple-pattern mutation; cannot be expressed as `property_*` because it requires reading and re-writing an ordered list of prior states, which is not a value the user authors directly. Stays in TS until a generic `stack_pop` grounding type is justified by ≥2 use cases.                                                                                           |
| ~~`planOnToday`~~            | Migrated #3136 — declarative `property_set` + `$todayStart` token                     | Closed as Q3.b exception 2026-05-17 — the legacy service merely wrote `ems__Effort_plannedStartTimestamp = YYYY-MM-DDT00:00:00`; no daily-note resolution involved. Migrated to declarative `property_set` using the new `$todayStart` substitution token (byte-identical output).                                                                                                                                          |
| ~~`createTaskForDailyNote`~~ | Migrated #3136 — declarative `create_instance` + `$targetFolder` + `propertyDefaults` | Closed as Q3.b exception 2026-05-17 — the legacy service merely created `ems__Task` in the target's parent folder with `plannedStartTimestamp = today`; no daily-note resolution. Migrated to `create_instance` once two general-purpose primitives landed: `$targetFolder` substitution (parent dir of target file) and `exocmd__Grounding_propertyDefaults` JSON literal (substituted defaults applied before userInput). |

Each exception is bound to a verifiable property of the substrate (non-RDF history list / platform metadata cache), not to TypeScript-implementation convenience. Re-evaluating an exception requires demonstrating that the substrate property changed (e.g. daily-note resolution becomes addressable as a pure SPARQL function over the vault graph).

## Methodology

`scripts/audit-starter-kit-groundings.mjs` walks `exocortex-starter-kit/exocmd/**/*.md`, extracts the two grounding properties via regex, joins against the static `KNOWN_REAL_SERVICE_IDS` / `KNOWN_STUB_SERVICE_IDS` sets mirrored from `CliServiceRegistryPopulator.ts`, and emits the JSON fixture committed at `docs/rfc-94e520da/starter-kit-grounding-status.json`. The fixture is the canonical input for the Phase 6 BDD scaffold (`expected.json` per scenario derives from the per-grounding row).

Re-run on every starter-kit change:

```bash
node scripts/audit-starter-kit-groundings.mjs \
  --starter-kit ../exocortex-starter-kit \
  --out docs/rfc-94e520da/starter-kit-grounding-status.json
```

Drift gate (Phase 6 prep): if the audit script ever finds a service id that is neither `REAL` nor `STUB` nor in the `KNOWN_UNREGISTERED` allowlist, it exits non-zero — that's the moment to either port the service or document the gap explicitly.
